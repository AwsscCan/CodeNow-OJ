# CodeNow OJ 陪伴式学习闭环设计

**日期**：2026-07-27
**状态**：主 Agent 全权批准进入实施计划
**范围**：围绕十个优先点子实现“预测风险 -> 陪写提醒 -> 失败反例 -> 复盘沉淀 -> 错题赢回”的学习闭环。

## 1. 目标

CodeNow OJ 现有能力已经包括 C++17 判题、提交记录、AI 对话、桌宠台词、用户记忆池、笔记和云端同步。本批次不扩展成大型 OJ，而是把现有数据转化为个性化学习陪伴：

1. AI 复盘报告。
2. 错题本 / 薄弱点雷达。
3. 同桌小纸条。
4. 用户雷区提醒。
5. 反例挑战模式。
6. 不直接给答案 / 提示等级。
7. 自我解释检查。
8. 题目知识卡片。
9. 赢回这一题。
10. 记忆可视化与可编辑。
11. AI 生成测试点响应过慢优化。

## 1.1 最高优先级：数据不得丢失

本批次所有实现都必须服从数据安全：

- 不得删除、清空或重写现有题目、测试点、提交记录、代码草稿、笔记、用户偏好、AI 对话和本地记忆。
- 不得运行 `git reset --hard`、`git checkout --`、批量删除、重新生成覆盖题库 JSON 等破坏性操作。
- 不得修改 `public/problems/*`、`public/catalog-index.json`、`public/contest-problems.json`、`drizzle/*`、`.data/*`，除非某个任务明确要求且主 Agent 单独批准；本批陪伴功能默认不需要触碰这些文件。
- UI 集成必须复用现有 `Problem.samples`、`SubmissionRecord`、`code_drafts`、`submissions` 和 localStorage 数据结构，不做破坏性迁移。
- 若需要新增字段，必须是可选字段或向后兼容的派生数据；旧 localStorage 和旧 D1 行必须能继续读取。
- 合并代理成果时只合并各 worktree 的小范围补丁，主工作区现有未提交改动一律保留。

## 2. 参考项目

- AI 复盘报告：`alibaba/open-code-review`、`vercel-labs/openreview`，借鉴结构化 AI 反馈。
- 错题雷达：CP Tracker、AlgoTrack、LeetCode tracker 类项目，借鉴进度与薄弱点统计。
- 同桌小纸条 / 记忆：`fiorastudio/buddy`、OpenPersona、MemPalace，借鉴陪伴式短反馈与用户可控记忆。
- 反例挑战：Hypothesis、fast-check、testlib，借鉴最小反例与生成式测试思想。
- 提示等级 / 自我解释：learn-codebase、OATutor，借鉴 Socratic tutoring 和 active recall。
- 题目知识卡片：USACO Guide、OI Wiki、cp-algorithms，借鉴知识标签、前置知识、常见坑。
- 赢回这一题：LeetCodeAnki、FSRS/Anki，借鉴复习调度与错题再挑战。
- 生成测试点性能：Hypothesis/fast-check 的渐进反馈思想、Judge0 batch/queue 优化思想，借鉴快速产出可用首批结果和并发验证。

## 3. 架构边界

本批次按“纯逻辑优先、UI 轻集成、AI 可降级”实施：

- `app/lib/learning/*`：学习分析纯函数，负责复盘输入摘要、弱点统计、反例提示、知识卡片、赢回调度。
- `app/stores/memory-store.ts`：扩展记忆条目的可编辑、固定、关闭与雷区分类。
- `app/stores/mascot-store.ts` / `app/stores/mascot-lines.ts`：扩展桌宠情绪状态和纸条事件，不引入频繁 AI 调用。
- `app/api/chat/route.ts`：加入提示等级、复盘、反问、自我解释等 prompt 策略。
- `app/problem/[id]/page.tsx`：仅做轻量入口集成，避免把所有业务逻辑塞回页面。
- `tests/unit/*`：每个功能先写失败测试，再实现最小逻辑。

## 4. 数据原则

- 优先复用 `SubmissionRecord`、`Result`、`Problem` 和现有 `MemoryEntry`。
- 不为“代码时间线”新增存储；解题轨迹从提交记录推导。
- 需要持久化的用户偏好和记忆继续走 localStorage，后续再接云同步。
- AI API Key 不进入新记忆、新复盘、新日志。
- 所有用户可控文本在进入 prompt 前压平换行、截断长度。
- 所有分析、雷达、复盘、挑战和赢回入口优先从现有数据派生；派生失败时显示空态，不写坏源数据。

## 5. 十个功能的验收边界

### 5.1 AI 复盘报告

输入题面、代码、最近判题结果、提交摘要，输出结构化复盘：`diagnosis`、`firstFailedHint`、`nextStep`、`avoidGivingAnswer`。没有 AI Key 时生成本地兜底复盘。

### 5.2 错题本 / 薄弱点雷达

从提交记录和记忆池统计 WA/TLE/CE/RE 分布、常见雷区、最近失败题目和复习优先级。

### 5.3 同桌小纸条

根据阶段和雷区生成短提示，默认本地规则，长度短，不弹大对话框；同一条短期内去重。

### 5.4 用户雷区提醒

把记忆分类为边界、溢出、复杂度、编译、运行时、输出格式、题意理解等雷区；只在题面或判题上下文相关时触发。

### 5.5 反例挑战模式

WA 后生成一个“小到能手算”的挑战对象：失败输入、期望、实际、引导问题。首期从已有失败测试点缩写/摘要，不凭空编造未知官方数据。

### 5.6 不直接给答案 / 提示等级

AI 请求支持 `hintLevel: direction | observation | pseudocode | full`，默认 `observation`。系统提示词明确禁止在低等级直接给完整代码。

### 5.7 自我解释检查

AC 后用户写一句解释，AI 或本地规则返回 `graspedCore`、`missingConcepts`、`followUpQuestion`。

### 5.8 题目知识卡片

为题目推导或生成知识卡片：算法标签、复杂度、常见坑、前置知识、变式方向。首期可本地启发式 + AI 补全。

### 5.9 赢回这一题

从失败历史和最后 AC 状态推导是否应复习，生成“上次输在哪里、今天挑战什么”的入口数据。

### 5.10 记忆可视化与可编辑

用户可列出、删除、固定、静音单条记忆；固定记忆不被容量淘汰，静音记忆不注入 AI prompt。

### 5.11 AI 生成测试点响应过慢优化

生成测试点应优先缩短“首批可用结果”的等待时间，并减少无意义的串行阻塞。首期优化范围包括：prompt/批量大小/超时预算的参数化、参考解验证并发、失败批次快速退避、可返回部分结果时不静默等待到总预算耗尽。所有性能优化必须有确定性单元测试锁定，不降低测试点质量报告的可信度。

## 6. 非目标

- 不做完整社交社区扩展。
- 不新增本地 C++ 沙箱。
- 不做复杂动画或大型 UI 重构。
- 不做排行榜、积分或强游戏化。
- 不把十个功能全部做成云端持久化。
- 不为了性能跳过安全校验、端点白名单、输入大小限制或参考解验证的可信度标记。

## 7. 测试要求

每个任务 Agent 必须遵守 TDD：

1. 写失败测试。
2. 运行目标测试，确认按预期失败。
3. 写最小实现。
4. 运行目标测试通过。
5. 汇报改动文件、测试命令、风险。

主 Agent 负责最终集成、冲突处理和全量验证。

额外数据安全门禁：

1. 合并前检查每个任务 diff，确认没有触碰题库 JSON、迁移、数据库文件或删除测试点/提交记录逻辑。
2. 针对任何 store schema 改动补充兼容旧 localStorage 的测试。
3. 最终运行提交记录、题库加载、问题仓储、导入/同步相关既有测试，确保现有数据链路不回退。
