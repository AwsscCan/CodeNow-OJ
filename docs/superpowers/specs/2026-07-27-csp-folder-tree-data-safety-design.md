# CSP 数据补全与文件夹树无损操作设计

## 背景与目标

当前发布产物只有 16 道第 33-42 次 CSP 认证题，而且既有届次映射与标题存在错误。每届应有 5 道，10 届应为 50 道。权威数据来源采用曙梦 OJ 的 CSP 分类与详情页。

题库目录已支持同级排序和拖入子目录，但不能把子目录提升到上级或根级。本地“解散”还会移除整棵子树并把所有后代题目挪走，前端对云端解散后的路径映射也有相同偏差。

本次目标：

1. CSP 认证第 33-42 次发布题目从 16 道补齐到 50 道，每届题号 1-5 完整，生成索引与单题文件。
2. “全部题目”作为虚拟总文件夹和目录树根节点，可接收目录拖放，使目录成为根级目录。
3. 文件夹可在任意合法层级移动：同级排序、拖入成为子文件夹、拖到其他层级的行前/行后成为该行同级、拖到“全部题目”成为根级。
4. 解散只删除当前目录：本级题目移到上级，直接子目录提升一级，子目录内部结构保持不变。
5. 普通移动与解散不得删除题目、测试点、代码草稿或提交记录。
6. 保留“永久删除”；二次确认后删除目标目录整棵子树内的本地题目。提交记录仍作为历史记录保留，云端当前 API 不提供题目级联删除，因此云端目录删除继续采用无损提升语义，并在界面文案中明确。
7. 内置文件夹没有操作特权：`默认题库`、AcWing、CSP 等目录与普通本地目录一样可移动、排序、解散和永久删除。

## 方案比较

### 方案 A：继续在页面事件中直接拼接路径

改动最少，但移动、解散、排序会继续分散在 React 页面和 Zustand store 中。本地与云端容易再次出现语义不一致，路径冲突和环检测也难以单测。

### 方案 B：建立路径树操作纯函数，由本地和云端适配层复用（采用）

新增聚焦的目录树模块，提供移动整棵子树、解散本级和排序计算。纯函数返回新的路径与题目目录映射，页面只负责拖放落点判定及调用云端 API。该方案可用表驱动测试覆盖所有层级，且不改变现有持久化格式。

### 方案 C：把本地目录迁移为 ID/parentId 模型

长期最稳健，但需要迁移 localStorage、导入清单、云端同步和大量 UI 消费者，超出本次需求且数据迁移风险更高。

## 数据模型与操作语义

保留现有本地路径字符串模型。新增虚拟根标识只存在于交互层，“全部题目”不会写入 `folders`。题目可直接位于虚拟根，持久化路径为 `""`。

内置题数据文件继续保持只读，store 新增持久化的 `builtinFolderOverrides: Record<problemId, path>`。渲染目录与筛选题目时先应用覆盖路径。移动或解散内置目录只更新覆盖映射；永久删除内置目录时把对应题号写入既有 `hiddenBuiltins`。这让内置目录获得与普通本地目录相同的交互能力，同时不篡改发布 JSON 与完整测试点。

- `moveFolderTree(source, destinationParent)`：移动 source 及其全部后代，只重写路径前缀和归档的 `folder` 字段。
- 行中段落点：`destinationParent = target`，成为 target 子目录。
- 行上/下边缘落点：`destinationParent = folderParent(target)`，成为 target 同级，并更新该父级的排序。
- “全部题目”落点：`destinationParent = ""`，成为根级。
- 禁止跨本地/云端目录移动、移入自身或后代、超过 5 层、目标同名冲突；内置目录与普通本地目录不做区分。
- `dissolveFolderLevel(folder)`：删除 folder 本身；本级题目改到父级（根目录的本级题目进入虚拟根，路径为 `""`；云端根目录回退到“云端题库”）；每个直接或间接后代去掉 folder 这一层前缀，保留剩余层次。
- `deleteFolder`：本地保留危险操作语义，二次确认后删除目录整棵子树和其中题目；提交历史不按目录或题目删除。云端因现有仓库 API 的 `deleteFolder` 是无损提升，不伪装成题目删除。

目录操作不修改 `Problem.samples`、云端 `test_cases`、本地工作区 history 或云端 `submissions`。本地归档更新采用对象展开保留完整 `problem`；云端只 PATCH 文件夹 `parentId` 或 DELETE 文件夹，由数据库外键与仓库事务保持题目和测试点。

## CSP 数据流

使用 Playwright 脚本 `import-csp-shumeng.mjs` 抓取并固化 50 道真实题面、输入输出格式和公开样例，淘汰三份错误的旧 CSP 定义。生成流程为：

`oj.shumeng.tech -> csp-cert-source.json -> generate-bundled -> public/contest-problems.json -> split-catalog -> public/catalog-index.json + public/problems/CS*.json`

契约测试直接读取生成产物，要求：CSP 认证题严格覆盖 `CS0331..CS0335` 至 `CS0421..CS0425` 共 50 个 ID；每届恰有 5 道且题号 1-5 无缺口；逐题标题与来源 URL 匹配曙梦 OJ；每题至少保留一组来源站公开样例；轻量索引和单题文件均包含全部 50 道题。来源站未公开的隐藏评测数据不得伪造。

## 异常与冲突处理

所有无效拖放在写状态或请求云端前拒绝，并给出具体 toast。云端请求失败时不更新前端路径缓存。目录移动的同名冲突按完整目标路径判断。移动整棵子树后若深度超过 5 级，整个操作拒绝。

## 测试设计

1. 纯函数单测：根级移动、跨层同级移动、拖入、环拒绝、深度拒绝、同名冲突、解散只提升一级、归档 samples 原样保留。
2. 组件测试：拖到“全部题目”提升为根级；拖到不同父级目录的上/下边缘成为目标同级；中段仍为子目录；危险删除仍需确认。
3. 内置目录测试：默认题库和 CSP/AcWing 目录出现相同操作菜单，可移动/解散；永久删除确认后隐藏目录内内置题，取消确认不变。
4. 仓库/API 测试：云端删除本级目录后题目和直接子目录提升，测试点仍可读取。
5. CSP 产物测试：先观察旧标题/届次映射失败，再从权威来源导入并重建到严格 50 道，逐届校验 5 道及逐题标题/URL。
6. 回归：完整单元测试、lint、生产构建。

## 验收标准

- 用户能把任意可编辑目录拖入另一个目录、拖到任意目录的前后成为同级、拖到“全部题目”成为根目录。
- 内置目录与普通本地目录具有相同菜单和拖放能力，不出现“内置目录不支持”分支。
- 解散 `A/B` 后，`A/B` 的题目进入 `A`，`A/B/C/D` 变为 `A/C/D`。
- 移动和解散前后题目数量、每题测试点内容、提交记录数量不变。
- 永久删除继续显示二次确认，只有确认后才删除本地目标子树和其中题目。
- CSP 认证发布产物为 50 道，第 33-42 次每届题号 1-5 完整，全部可从轻量索引打开并加载来源站公开样例。
